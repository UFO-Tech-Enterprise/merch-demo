# Spec 001: Merchandising Role Demo

Status: draft.

Purpose: prepare a client-facing demo presentation for merchandising roles: merchandiser, merchandising supervisor, KAM, and photo controller `PCTL`.

## Admin Sources

The admin contour is based on these microfrontends:

- `users`: user list, profile photo, phone, main role, all roles, internal/external type.
- `employees`: positions, role, manager, role context, links, self route.
- `markets`: TT base, filters, import, create TT, verify address, TT card, contracts, shelf config, tasks tab.
- `routes`: всі маршрути, мої маршрути за роллю, перегляд маршруту, створення маршруту, додавання ТТ, графік, денний маршрут, зміна порядку перетягуванням, групові операції.
- `photoreports`: photo report queue, date filters, TT accordions, task cards, photo verification, assignments, final task confirmation.

The presentation uses only merchandising, supervision, KAM, and photo-control scenarios. Tabs and functions outside this context are not part of the deck.

## Main Screen Copy

Headline:

> Єдиний процес від візиту в торгову точку до прозорого контролю якості.

Body:

> Рішення об'єднує польові візити, контроль виконання та управління ключовими торговими точками в єдиний процес. Кожна роль бачить власний сценарій роботи, а керівництво отримує прозору картину якості мерчендайзингу.

## Role Summaries

Мерчендайзер:

- Застосунок: маршрут, картка ТТ, чек-лист, камера, черга синхронізації, офлайн-збереження даних, залишки, полиці, ДМП, промо-цінники, асортиментна матриця, доручення.

Супервайзер мерчендайзерів:

- Застосунок: команда, активний маршрут підлеглого, QR-підтвердження, допомога у виконанні задачі, дашборд підлеглого.
- Admin: users/employees, база ТТ, імпорт контрактів, маршрути, графіки, додавання ТТ, групові операції, створення ТТ, верифікація адреси, доручення.

KAM:

- Застосунок: власний маршрут, додавання ключової ТТ у план дня, план робіт, персональний дашборд.

Фотоконтролер `PCTL`:

- Admin: черга фотозвітів, розкриття задач, картки фото, оцінка відповідності, створення доручення, фінальне підтвердження.

## Slide Catalogue

Merchandiser Застосунок:

- Робочий день починається з готового плану.
- Черга синхронізації захищає результат роботи від втрати.
- Маршрут перетворює список адрес на керований план обходу.
- Картка торгової точки збирає контекст перед аудитом.
- Чек-лист веде візит по стандартизованому сценарію.
- Камера створена для доказового мерчендайзингу.
- Нижня панель пришвидшує аудит прямо біля полиці.
- Аудит залишків показує фактичну присутність товару.
- Розмір полиць переводить торгове обладнання в дані.
- Додаткові місця розміщення контролюються по кожній домовленості.
- Фото промо-цінників підтверджує коректність акційної комунікації.
- Асортиментна матриця робить полицю вимірюваним стандартом.
- Доручення закривають разові задачі без хаосу в комунікації.

Supervisor Застосунок:

- Супервайзер бачить живу картину команди.
- Підключення маршруту відкриває реальний стан польового дня.
- QR-підтвердження вирішує складні ситуації на точці.
- Супервайзер може допомогти завершити критичний крок.
- Детальний дашборд підлеглого показує персональний прогрес.

Supervisor Admin:

- Супервайзер керує командою через користувачів, посади і рольові зв'язки.
- Список торгових точок є основою маршрутів і польових задач.
- Маршрутизація команди стає прозорою системою покриття.
- Імпорт контрактів масово створює домовленості для торгових точок.
- Графік візитів налаштовується на рівні кожної торгової точки.
- Нові точки додаються до маршруту масово і з потрібним графіком.
- Груповий режим прискорює зміни у великих маршрутах.
- Нову торгову точку можна створити без втрати якості довідника.
- Адреса і координати ТТ проходять керовану верифікацію.
- Доручення переводять точкові прохання у контрольований процес.

KAM Застосунок:

- KAM працює з власним маршрутом ключових точок.
- Ключову ТТ можна додати у сьогоднішній план за кілька секунд.
- План робіт тримає активності по ключових ТТ в одному місці.
- Дашборд показує стан власного контуру KAM.

PCTL Admin:

- Фотоконтролер працює зі списком задач, згрупованих по даті та ТТ.
- Усередині ТТ видно задачі, готовність підзадач і дію перевірки.
- Фото перевіряється разом із плановим значенням і коментарем.
- За результатом перевірки можна створити доручення.
- Після підтвердження задача блокується від змін.
